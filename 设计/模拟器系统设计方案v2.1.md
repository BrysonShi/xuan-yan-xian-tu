# 命运模拟器系统设计方案 v2.1

> 修订说明：基于游戏体验评审（3.6/5）和技术架构评审（3.6/5）的反馈，修订核心机制。
> 修订日期：2026-08-18

## 〇、核心原则（不变）

**模拟器的爽点 = 信息差优势**
玩家通过模拟预知未来 → 在现实中获得别人没有的信息 → 做出更优决策 → 感受到"我因为预知而改变了命运"的爽感。

---

## 一、核心循环（修订）

```
现实剧情（沉浸叙事）→ 到达安全区（洞府/营地）→ 花费灵石启动模拟
    ↑                                                    ↓
    ← 「命运改写」特效 ← 🔮预知选项改变现实 ← 死亡复盘+记忆碎片 ← 模拟结束
```

## 二、消耗与次数（重大修订）

### 2.1 消耗表（v2.1 修订）

**修订逻辑**：先建立灵石收入预估，再确保每个境界每天至少能模拟 1-2 次。

| 境界 | 预估日收入 | 单次消耗(≈日收入40%) | 每日上限 | 日最大消耗 |
|------|-----------|-------------------|---------|-----------|
| 炼气1-3层 | 15-25 | **8** | 3 | 24 |
| 炼气4-6层 | 30-50 | **15** | 4 | 60 |
| 炼气7-9层 | 60-100 | **30** | 5 | 150 |
| 筑基+ | 150-250 | **60** | 6 | 360 |

**设计约束**：单次消耗 = 日收入的 30%-50%，确保每天至少 1-2 次（核心循环不断），偶尔攒到 3 次以上（有富余感）。

### 2.2 消耗资源统一

**统一为灵石（spiritStones）**，废弃"天机点"概念。
- 设计简洁：只有一个核心消耗资源
- 与小说设定一致（小说里都是花灵石）
- 代码中所有引用 destinyPoints 的地方改为 spiritStones

### 2.3 每日次数重置

- 使用 UTC 日期判断（`new Date().toISOString().slice(0, 10)`）
- 代码中所有 `sim_daily` 读取使用可选链防御：`player.flags.sim_daily?.count ?? 0`
- 新增存档迁移函数，兼容旧存档

## 三、模拟触发约束（新增）

### 3.1 安全区机制

模拟**只能在安全场景**启动：
- 洞府（cave）
- 丙字院宿舍（start）
- 营地/客栈（未来章节）

**实现方式**：场景数据增加 `isSafeZone: true` 标记，RealityView 的 startSimulation 检查当前场景是否有此标记。

```javascript
// storyGraph 场景扩展
'start': { isSafeZone: true, ... },
'cave': { isSafeZone: true, ... },
'ch2_1': { isSafeZone: true, ... }, // 模拟器觉醒场景

// 非安全区
'forest_1': { isSafeZone: false, ... }, // 默认就是 false
```

### 3.2 剧情保护期

关键剧情进行中（如正在与 NPC 对话、处于战斗场景）时，模拟按钮自动锁定。
- 简单实现：如果当前场景有 `npc` 字段，锁定模拟。

## 四、模拟内容生成（重大修订）

### 4.1 图遍历引擎（替代浅层随机）

```javascript
/**
 * 从起始场景出发，随机深度遍历 storyGraph
 * @param {string} startSceneId - 起始场景 ID
 * @param {number} maxDepth - 最大遍历深度（默认 3-5）
 * @returns {string} 到达的场景 ID
 */
function getRandomReachableScene(startSceneId, maxDepth = 3) {
  let current = [startSceneId];
  for (let d = 0; d < maxDepth; d++) {
    const nextSet = new Set();
    for (const id of current) {
      const scene = storyGraph[id];
      if (scene?.choices) {
        scene.choices.forEach(c => {
          if (c.next && storyGraph[c.next]) nextSet.add(c.next);
        });
      }
    }
    if (nextSet.size === 0) break;
    // 每层有 30% 概率停止（模拟"命运分支的不确定性"）
    if (d > 0 && Math.random() < 0.3) break;
    current = [...nextSet];
  }
  return current[Math.floor(Math.random() * current.length)];
}
```

### 4.3 天机反噬（修正公式）

**修订要点**：
1. 反转境界因子——高境界活得久
2. 前 5 年免疫（保底）
3. 对数增长（而非线性）
4. 封顶概率从 30% 降到 15%

```javascript
function getDeathProbability(yearsElapsed, realmLevel) {
  // 前 5 年免疫天机反噬
  if (yearsElapsed < 5) return 0;
  
  const baseChance = 0.01;
  // 高境界减免：炼气九层减免 40%
  const realmResist = 1 - realmLevel * 0.05;
  // 超线性增长，30 年后急剧增加
  const timeFactor = Math.pow((yearsElapsed - 5) / 30, 1.5);
  
  const p = baseChance * realmResist * timeFactor;
  return Math.min(0.15, p);
}
```

## 五、记忆碎片系统（重大修订）

### 5.1 碎片匹配：标签机制（替代白名单）

```javascript

  id: 'insight_liufei_pattern',
  name: '柳飞的暗器习惯',

  used: false,

// 场景也带标签
'ch2_4': {
  text: '...',
  tags: ['npc:liufei', 'conflict:对决'],
  // ...
}

// 匹配逻辑
function findMatchingInsights(scene, fragments) {
  const sceneTags = scene.tags || [];
  return fragments.filter(f => 
    !f.used && f.matchTags.some(tag => sceneTags.includes(tag))
  );
}
```

### 5.2 碎片管理

| 项目 | 规则 |
|------|------|
| **槽位上限** | 初始 5 个，炼气 4-6 层 8 个，炼气 7-9 层 12 个 |
| **保底获取** | 每次模拟至少产出 1 个碎片 |
| **额外获取** | 30% 概率额外产出 1 个；S 评价保证 2 个 |
| **碎片时效** | 跨章节后标记为"过时"，可用但不再在预知选项中高亮显示 |
| **命名统一** | 废弃 `simInsights`，统一使用 `memoryFragments` |

### 5.3 预知选项

当现实剧情到达关键节点时，如果玩家持有匹配的记忆碎片，解锁预知选项：

```
正常选项：
A. 接受柳飞的好意
B. 礼貌拒绝

🔮 预知选项（需要碎片：柳飞的暗器习惯）：
C. 🔮 提前防备他的暗器（消耗碎片）
```

**使用时增加「命运改写」特效叙事**：
```
「命运的丝线因你的预知而偏移——」
「柳飞的风刃从背后袭来，但你早已侧身闪避。他的表情从得意变为震惊。」
「你改变了命运。」
```

### 6.1 死因叙事

每次模拟死亡后，用 1-2 句精炼文本展示死因和关键教训：

```

💀 死因：被柳飞的风刃从背后击杀

「存活时间：2年3个月 | 最终境界：炼气四层 | 评价：★★☆☆☆」
```

### 6.2 死亡信息转化

死亡本身成为信息收获：
- 死亡场景的标签会产出记忆碎片
- 下次模拟时，如果持有"死因相关碎片"，初始几年死亡概率降低（"你已经知道了危险在哪"）

## 八、存档迁移（新增）

```javascript
function migrateSaveData(data) {
  const version = data.version || '0.0.0';
  
  // 0.1.0 → 0.2.0
  if (!data.flags) data.flags = {};
  if (!data.flags.sim_daily) {
    data.flags.sim_daily = { date: '', count: 0 };
  }
  if (!data.memoryFragments) {
    data.memoryFragments = [];
  }
  // 迁移 simInsights → memoryFragments
  if (data.simInsights?.length && !data.memoryFragments?.length) {
    data.memoryFragments = data.simInsights.map(id => ({
      id, name: id, description: '', matchTags: [], used: false,
    }));
  }
  delete data.simInsights;
  
  data.version = '0.2.0';
  return data;
}
```
